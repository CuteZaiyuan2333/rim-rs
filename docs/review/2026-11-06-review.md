### N-008 C# 构建无条件依赖游戏探测（中）——已实现（批次 A）

位置：`crates/rim-rs/src/builder.rs`（`build_csharp`）

`build_csharp()` 总是先 `GameInstall::locate(...)`，即使调用方通过 `csharp_reference(...)` 手动提供了全部依赖 DLL。在无游戏安装的环境（CI、批量语法检查）想编译 C# 会被 `GameDirNotFound` 挡住。

方向：

- 当显式引用列表覆盖了默认需要的程序集时允许跳过探测；或
- 新增 `BuildOptions::skip_game_probe(bool)` / `.game_root(None)` 语义，并在文档说明引用责任完全由调用方承担。

验收：无 `RIMWORLD_DIR` 且无本地安装时，显式引用的 C# 构建可以成功并有测试覆盖（fake runner）。

实现记录（2026-11-06，批次 A）：

- 采取显式开关：`BuildOptions::game_probe(bool)`（默认 `true`）。为 `false` 时 C# 阶段完全跳过 `GameInstall::locate` / `require_16` 与自动 Harmony 引用；引用责任完全在调用方。
- fail-loudly：`game_probe(false)` 且未提供任何 `csharp_reference(...)` 时在 `validate()` 阶段报新错误 `Error::GameProbeWithoutReferences`，先于任何文件写入。
- 为覆盖“跳过”分支新增可注入点：`BuildOptions::runner(Option<Arc<dyn CommandRunner>>)`（默认 `SystemRunner`，行为不变）；`dotnet.rs` 为 `Arc<T: CommandRunner + ?Sized>` 补了转发 impl。builder 层 fake runner 会在 `dotnet build -o` 时写出预期 DLL，使整条流水线（写 csproj → 调 dotnet → 校验 DLL → 拷入 staging）在无游戏、无 SDK 环境下可端到端测试。
- 测试：`builds_csharp_without_a_game_when_probe_is_disabled`（成功路径）、`rejects_probe_disabled_without_explicit_references`（失败路径）、`csharp_build_still_probes_the_game_by_default`（默认行为回归保护）、`surfaces_injected_dotnet_failures`（注入 runner 的错误透传）。
- 注意：`game_probe(false)` 只作用于 C# 阶段；`deploy` 无显式 `mods_dir` 时仍需游戏安装，`.game_dir(...)` 对关闭探测时的 C# 阶段无效。

### N-009 `work/`、`out/`、`csharp/` 为共享固定名（低）——已实现（批次 B）

位置：`crates/rim-rs/src/builder.rs`

同一 `base_dir` 顺序构建第二个 mod 会删掉第一个 mod 的 `csharp/`、`work/Mod.csproj`、`out/`。当前 API 一次 `build()` 只处理一个 mod，问题只在多次构建中间产物被覆盖时出现。

方向：中间子目录按 mod 名（`sanitize_dir_name`）隔离，如 `.rim-rs/stage/<Mod>/`、`.rim-rs/work/<Mod>/`。注意 `out/` 内 DLL 名已含 assembly name，真正的覆盖点是 `work/` 与 `csharp/`。

实现记录（2026-11-06，批次 B）：

- `build_csharp()` 的三个中间目录统一改为按 `sanitize_dir_name(&name)` 隔离：`.rim-rs/csharp/<Mod>/`、`.rim-rs/work/<Mod>/`、`.rim-rs/out/<Mod>/`；`stage/` 原本已隔离，不变。`out/` 虽然 DLL 名可区分，但共享目录会被下一个 mod 构建的 `remove_dir_all` 整体清除，因此与其他目录保持同一条隔离规则，文档已说明。
- 测试：`isolates_intermediate_dirs_per_mod`（同一 `base_dir` 连续构建两个 mod，断言第一个 mod 的 `csharp/` 源码、`work/` 的 `.csproj` 与 `out/` 的 DLL 在第二次构建后仍存在）。
- 目录约定文档（DESIGN §5.1 / §5.4、README 设计约束与 C# 输入小节）同步更新。

### N-010 校验黑名单过宽的误报面（低）

位置：`crates/rim-rs/src/package.rs`（`validate_mod_dir`）

路径任意层级出现组件 `src`（如 `Textures/src/x.png`）、文件名 `Cargo.lock`、`*.toml` 等都会被拒。MVP 阶段可接受，但若未来支持 `Languages/` 之类携带任意子目录的资源，会出现合法文件无法打包。

方向：仅对顶级目录或明确的工程目录结构应用黑名单，或把误报项做成 warning 供用户选择。
